## 2. 产品定义

DeepMe 是一个自带作者公开知识库的在线问答产品。

默认页面连接作者的公开知识库。访客可以询问作者的项目经历、技术决策、失败复盘和个人观点，回答必须引用知识库中的原始证据。

用户也可以上传自己的文件，在独立的临时空间内进行问答。开源用户可以拉取项目，把默认知识目录替换成自己的知识库并自行部署。

一句话定位

> 面试我之前，先问我的知识库。

## 3. 背景

DeepMemo 当前已经发展为包含 Editor、QA、Wiki、Knowledge Cards、Daily Pulse 和文件管理的个人知识工作台。功能完整，但前端信息架构较重，不适合直接作为公开在线产品。

DeepMe 需要把产品重心重新放回问答。

- 对外展示作者长期积累的项目记录与判断。
- 让面试官通过可追溯问答提前了解作者。
- 让普通用户上传文件后快速获得同样的问答体验。
- 让开发者拉取项目并替换知识库，而不必接受一整套复杂知识管理工作流。

## 4. 产品目标

### 4.1 MVP 目标

1. 提供一个默认连接作者公开知识库的在线问答首页。
2. 回答必须基于证据，并展示可点击的来源引用。
3. 提供独立的文件上传问答模式，不与作者知识库混用。
4. 支持公开知识库按日同步，并展示当前知识版本和更新时间。
5. 支持开源用户通过配置知识目录部署自己的版本。
6. 大幅简化公开前端，只保留问答、上传和引用所需界面。

### 4.2 非目标

MVP 不包含以下内容。

- 不提供用户注册、个人主页或公开知识分身广场。
- 不提供在线长期知识库托管。
- 不提供多人协作编辑。
- 不在公开前端提供 Markdown 编辑器、Wiki 审核和 Knowledge Cards 管理。
- 不把用户上传内容用于训练、作者知识库更新或其他用户问答。
- 不自动把作者的私人日记发布到公开知识库。
- 不支持作者知识库与用户上传文件的混合检索。
- 不默认启用 Web Search。

## 5. 用户与核心场景

### 5.1 访客

典型用户包括面试官、招聘方、开源项目访问者和希望了解作者的人。

核心任务

- 询问作者做过哪些项目。
- 深挖某个项目中的个人贡献和技术取舍。
- 查看回答对应的原始记录。
- 判断哪些信息有充分证据，哪些问题仍需本人回答。

### 5.2 文件问答用户

这类用户只想临时上传自己的资料并提问，不需要创建公开主页。

核心任务

- 上传 Markdown、TXT 或 PDF 文件。
- 等待文件解析完成。
- 只基于上传内容连续追问。
- 查看引用并在结束后立即删除资料。

### 5.3 自部署用户

这类用户从代码仓库拉取项目，在本地或自己的服务器部署。

核心任务

- 替换默认知识目录。
- 配置站点名称、简介和头像。
- 配置自己的模型服务。
- 通过 Docker Compose 或标准命令启动。

## 6. 产品原则

### 6.1 证据优先

回答中的事实必须来自当前知识范围。系统找不到可靠证据时，应明确说明知识库没有相关记录，不能使用模型常识补写作者经历。

### 6.2 知识范围可见

页面必须持续显示当前问答使用的知识范围。

- `作者的公开知识库`
- `你上传的 5 个文件`

切换模式后，新问题只能访问新模式对应的知识范围。

### 6.3 默认隔离

作者知识库、用户上传文件和不同上传会话之间必须隔离。任何检索、引用、历史消息和缓存都必须绑定明确的 `knowledge_scope_id`。

### 6.4 本地真值

沿用 DeepMemo 工程宪法。Markdown 原文仍是作者知识的长期真值，索引、卡片、摘要和模型输出都不能替代原始文件。

### 6.5 简单优先

公开产品首先解决提问、回答和核对证据。知识编辑与治理能力可以保留在内部工具或代码中，但不进入公开首页。

## 7. 信息架构

### 7.1 顶层模式

公开页面只有两个模式。

| 模式 | 默认知识范围 | 主要动作 |
| --- | --- | --- |
| 问我 | 作者公开知识库 | 提问、追问、查看引用 |
| 问你的资料 | 当前上传空间 | 上传、提问、删除 |

### 7.2 问我页面

页面包含

- 作者头像、姓名和一句话介绍。
- 产品主标题与可信度说明。
- 推荐问题。
- 对话消息区。
- 输入框和停止生成按钮。
- 当前知识版本和最后更新时间。
- 回答引用面板。
- 切换到文件问答的入口。

推荐问题至少覆盖

- 你最近负责的项目是什么？
- 你在灵感 Agent 项目中具体做了什么？
- 你做过哪些技术取舍？
- 哪次实验结果推翻了原来的判断？
- 你的开源贡献主要集中在哪些方向？

### 7.3 问你的资料页面

未上传时显示上传区域、支持格式、大小限制和隐私说明。

上传完成后显示

- 文件列表和解析状态。
- 当前知识范围。
- 对话消息区。
- 引用面板。
- 继续添加文件按钮。
- 立即删除空间按钮。
- 自动删除倒计时。

### 7.4 移动端

移动端使用单栏布局。引用面板改为底部抽屉，不保留固定左右侧栏。

## 8. 核心流程

### 8.1 默认知识库问答

1. 用户打开首页，默认进入“问我”。
2. 页面显示作者简介、推荐问题和知识更新时间。
3. 用户输入问题。
4. 系统只检索作者公开知识库。
5. 系统流式生成回答，并为事实陈述附加引用。
6. 用户点击引用，查看文件名、行号和原始片段。
7. 本地证据不足时，系统明确拒绝代答并提示用户询问本人。

### 8.2 文件上传问答

1. 用户切换到“问你的资料”。
2. 系统创建匿名临时空间。
3. 用户上传文件。
4. 系统完成格式校验、文本提取、切片和索引。
5. 页面显示解析成功或失败的文件。
6. 用户提问，系统只检索当前临时空间。
7. 用户主动删除，或空间到期后自动删除文件、索引和会话。

### 8.3 自部署

1. 用户拉取代码仓库。
2. 用户复制示例配置。
3. 用户把 Markdown 放入指定知识目录。
4. 用户配置模型、站点资料和知识路径。
5. 用户启动服务并执行首次索引。
6. 首页使用用户自己的站点资料和知识库。

## 9. 功能需求

### 9.1 P0 默认知识库

- 系统必须支持一个只读的默认公开知识范围。
- 默认知识范围必须通过配置指定，不能写死作者本地绝对路径。
- 默认知识包必须与私人 `data/` 目录分开。
- 页面必须显示知识版本、构建时间和最后成功更新时间。
- 同步失败时必须继续使用上一个成功版本。
- 新版本必须在索引和基础回归检查完成后原子发布。

### 9.2 P0 问答与引用

- 保留 SSE 流式输出。
- 保留 Query Rewrite、Local Search 和 Answer Composer。
- 保留数字引用与原始证据片段。
- 每个回答必须记录 `knowledge_scope_id` 和 `knowledge_version`。
- 有事实陈述但没有引用的回答视为失败。
- 没有足够证据时必须返回统一的无答案状态。
- MVP 不使用 Web Search 补充作者经历或上传文件内容。

### 9.3 P0 临时上传空间

- MVP 支持 `.md`、`.txt` 和 `.pdf`。
- 默认最多上传20个文件，总大小不超过50 MB，限制必须可配置。
- 每个空间使用不可预测的 `workspace_id`。
- 空间通过安全 Cookie 或等价机制绑定当前浏览器会话。
- 上传空间默认24小时后删除，TTL 必须可配置。
- 用户可以提前删除空间。
- 删除必须覆盖原始文件、解析文本、索引、缓存和聊天记录。
- 上传内容不能进入默认知识库、Knowledge Cards 或训练数据。

### 9.4 P0 知识范围隔离

- 每次检索必须显式携带 `knowledge_scope_id`。
- 默认知识问答不能读取临时空间。
- 临时空间不能读取默认知识库。
- 不同临时空间不能互相读取。
- 对话历史、引用和缓存不能跨范围复用。
- 范围缺失或无效时，后端必须拒绝请求，不能回退到默认知识库。

### 9.5 P0 公开知识库更新

MVP 将“同步公开知识包”和“从私人材料提炼新知识”视为两个流程。

公开知识包同步

1. 公开知识包由独立目录或独立仓库提供。
2. 定时任务每天检查一次变更。
3. 系统记录源文件路径、SHA256、修改时间和知识包版本。
4. 系统只处理新增、修改和删除的文件。
5. 发布前执行敏感信息扫描、索引构建和固定问题回归。
6. 全部通过后切换到新版本。
7. 失败时保留旧版本并记录错误。

私人材料提炼

- MVP 不自动发布私人日记。
- 后续版本可以从私人材料生成候选知识。
- 候选知识必须保留来源并由作者审核后进入公开知识包。

### 9.6 P0 自部署配置

至少提供以下配置。

```text
DEEPME_KB_PATH
DEEPME_SITE_NAME
DEEPME_SITE_BIO
DEEPME_SITE_AVATAR
DEEPME_UPLOAD_ENABLED
DEEPME_UPLOAD_TTL_HOURS
DEEPME_UPLOAD_MAX_FILES
DEEPME_UPLOAD_MAX_BYTES
```

仓库必须提供

- 示例环境变量。
- 示例公开知识包。
- Docker Compose 启动方式。
- 首次索引命令。
- 替换知识库的最短操作说明。

### 9.7 P1 问题反馈

- 记录无答案和低置信度问题。
- 管理端可以按频次查看问题。
- 问题只能用于提示作者补充知识，不能自动生成并发布事实。
- 默认不保存用户上传文件中的原文问题。

## 10. 知识与回答规范

### 10.1 作者身份边界

系统可以基于记录总结作者的经历与判断，但不能声称自己就是作者本人。

推荐表达

- “根据作者在 2026 年 8 月的项目记录……”
- “现有知识库没有记录这个问题，建议在正式面试时向本人确认。”

禁止表达

- “我当时就是这么想的。”，除非原文存在明确第一人称记录并保留引用。
- 没有来源的性格判断、成绩、项目贡献或技术能力结论。

### 10.2 引用规范

每条引用至少包含

- 来源文件。
- 行号或页码。
- 原始片段。
- 知识版本。

用户应能从回答中的 `[1]`、`[2]` 直接打开对应证据。

### 10.3 无答案规范

无答案回复应包含

- 当前未找到足够证据。
- 已检索的知识范围。
- 一个更具体的追问建议，或提示询问作者本人。

无答案时不能触发默认模型知识补全。

## 11. 隐私与安全

- 作者线上实例只能加载经过筛选的公开知识包。
- 部署密钥、私人日记和本地绝对路径不得进入公开构建产物。
- 上传文件必须校验扩展名、MIME、大小和解析超时。
- PDF 解析过程必须限制资源使用。
- 文件名和文件内容不得拼接为服务器路径。
- 文档中的 Prompt Injection 只能作为资料内容，不能改变系统指令和检索范围。
- 服务日志不得记录完整上传文件内容。
- 产品必须明确说明上传内容不会用于训练。
- 删除和TTL清理必须有可验证的服务端结果。

## 12. 前端改造边界

### 12.1 保留

- QA 对话主流程。
- SSE 流式输出。
- Markdown 回答渲染。
- 引用查看。
- 会话内追问。
- 响应式布局。

### 12.2 从公开前端移除

- Editor Workspace。
- Wiki Workspace。
- Knowledge Cards 浏览与审核。
- Daily Pulse。
- 文件树与文件 CRUD。
- Slash Command 和知识维护命令。
- 面向作者的复杂状态面板。

这些能力可以暂时保留在后端或内部管理入口，但不得增加公开首页复杂度。

### 12.3 新增

- “问我”与“问你的资料”模式切换。
- 作者介绍和推荐问题。
- 当前知识范围提示。
- 知识版本和更新时间。
- 文件上传、解析状态与删除。
- 临时空间到期提示。
- 无证据回答状态。

## 13. 后端改造边界

### 13.1 保留

- FastAPI 服务。
- LLM Provider 配置。
- Query Rewriter。
- Local Search Agent。
- Answer Composer。
- 引用数据结构。
- SQLite 作为应用状态存储。

### 13.2 需要调整

- 所有会话和检索增加知识范围。
- 检索工具从单一 `data/` 根目录改为受控的范围根目录。
- 默认知识库改为版本化只读知识包。
- 新增上传、解析、删除和TTL清理接口。
- 新增知识包构建、验证和发布流程。
- 禁止临时上传触发 Conversation Memory 和 Knowledge Card 编译。

### 13.3 暂缓

- 向量数据库。
- 用户账户与长期云端存储。
- 多设备同步。
- 在线编辑器。
- 自动公开私人材料。

## 15. 成功指标

### 15.1 问答质量

- 有事实陈述的回答引用覆盖率不低于95%。
- 固定问题集的人工事实正确率不低于90%。
- 跨知识范围泄漏测试必须为0。
- 无证据问题不得生成作者经历。

### 15.2 产品体验

- 默认知识库最后成功更新时间不超过24小时。
- 支持格式内的文件解析成功率不低于95%。
- 上传失败时必须展示明确原因。
- 用户可以在两步内打开任意引用。

### 15.3 隐私

- 到期空间删除成功率为100%。
- 主动删除后，原始文件和索引不可继续检索。
- 公开构建不得包含敏感信息扫描命中项。

## 16. 验收场景

1. 访客询问作者参与的灵感 Agent 项目，系统返回有引用的项目说明。
2. 访客询问知识库没有记录的私人问题，系统拒绝推测并建议询问本人。
3. 用户上传一份 PDF 后提问，回答只引用该 PDF。
4. 用户在上传模式询问作者项目，系统不得回退到作者知识库。
5. 两个临时空间上传不同文件，相同问题只能得到各自文件中的答案。
6. 用户主动删除空间后，原文件、引用和历史消息均不可访问。
7. 临时空间超过TTL后自动删除。
8. 新公开知识版本构建失败，线上继续使用上一个成功版本。
9. 公开知识版本成功发布后，页面更新时间和回答版本同步变化。
10. 自部署用户替换知识目录后，首页不再检索示例或作者知识。

## 17. 版本计划

### 阶段一 公开知识分身

- 重做公开首页。
- 默认知识库问答。
- 引用、无答案状态和知识版本展示。
- 公开知识包的手动构建与发布。

### 阶段二 临时文件问答

- 文件上传与解析。
- 临时知识范围。
- TTL 和主动删除。
- 隔离与安全回归测试。

### 阶段三 每日同步与自部署

- 公开知识包按日增量同步。
- 固定问题回归与原子发布。
- Docker Compose 和配置化品牌信息。
- 无答案问题反馈。

## 18. 待确认事项

以下事项不阻塞 PRD 评审，但需要在技术设计前确认。

1. 作者公开知识包由当前仓库目录、独立私有仓库还是对象存储提供。
2. 每日同步采用自动发布，还是回归通过后等待作者确认。
3. PDF 是否需要 OCR，MVP 默认只支持可提取文本的 PDF。
4. 匿名会话是否保留24小时，还是浏览器关闭后立即失效。
5. 产品对外名称是否正式从 DeepMemo 改为 DeepMe，仓库名称是否同步修改。
